# Empty States Reference

Types, patterns, and examples for first-use, no-results, error, and cleared empty states.

---

## Empty State Types

| Type | When it appears | User's emotional state | Copy goal |
|------|----------------|----------------------|-----------|
| First-use | User has never created any data | Curious, maybe uncertain | Orient and encourage |
| No results | Search or filter returned nothing | Mildly frustrated | Acknowledge and redirect |
| Error | Content could not load | Frustrated or worried | Reassure and provide a path |
| Cleared | User deleted everything | Neutral to relieved | Confirm and enable next action |

---

## First-Use Empty State

The first-use empty state is the most important of the four. It is the moment a user encounters a feature for the first time and has no data yet. If the copy is weak here, they may never return.

### Pattern: explain, show the benefit, CTA

**Part 1: Explain what goes here**
One sentence. Plain language. Not marketing.
- "This is where your projects live."
- "Your team's shared files will appear here."

Do not start with "No projects yet" or "You have no data." That states the obvious and frames the moment as a deficit.

**Part 2: Show the benefit of filling it**
One sentence. Outcome-oriented.
- "Create one to start assigning tasks and tracking progress."
- "Upload your first file so your team can access it from anywhere."

**Part 3: CTA**
The single action that populates this state. Specific verb + noun.
- "Create project"
- "Upload file"
- "Add team member"

Do not use "Get started" as the CTA. Name the action.

### Visual integration

If an illustration accompanies the empty state, the copy should complement it, not repeat it. An illustration of an empty inbox does not need a headline that says "Your inbox is empty." Write for the illustration to carry the "empty" concept while the copy carries the "what to do."

## No-Results Empty State

The no-results state fires when a search or filter returns nothing. The user was looking for something specific. Do not make them feel like the failure is theirs.

### Pattern: acknowledge, suggest alternatives, offer a reset

**Part 1: Acknowledge the search**
Reference what they searched for when possible.
- "No results for 'Q3 budget report'"
- "No tasks match these filters"

Do not say "Nothing found." It is abrupt and offers no information.

**Part 2: Suggest alternatives or explain**
Help them understand why and what to try.
- "Check the spelling or try a shorter search term."
- "This filter combination may be too narrow. Try removing one filter."
- "Results older than 90 days are not included in search."

**Part 3: Offer to broaden or reset**
Give a link or button to remove the constraint.
- "Clear filters"
- "Search all projects"
- "Try a different term"

### Before/after: no-results state

**Before:**
- Headline: "No results found."
- No further copy. No CTA.

**After:**
- Headline: "No tasks match these filters"
- Body: "Try removing a filter to see more results."
- CTA: "Clear all filters"

---

## Error Empty State

This fires when content should be there but could not load. The user is not at fault. Do not make them feel like they are.

### Pattern: what happened, when to try again, alternative actions

**Part 1: What happened**
Brief and honest. Do not blame the user.
- "We could not load your projects."
- "This file is not available right now."

**Part 2: When to try again**
Give a timeframe if you have one. If not, offer a retry.
- "Refresh the page to try again."
- "This usually clears up in a few minutes."

**Part 3: Alternative action**
Give the user somewhere to go if retry does not work.
- "If this keeps happening, contact support."
- "Go back to the dashboard"

Do not write "An error occurred." It describes nothing. Do not write "Our engineers have been notified." They may not have been, and it does not help the user anyway.

### Before/after: error empty state

**Before:**
- Headline: "Error loading content"
- Body: "Please try again later."

**After:**
- Headline: "We could not load your files"
- Body: "This is on our end, not yours. Refresh the page to try again."
- CTA: "Refresh"
- Secondary: "Contact support" (linked)

## Cleared Empty State

When a user deletes all items in a list or clears a space themselves, the empty state should confirm the action and prompt the next step. They are not stuck -- they chose to be here.

### Pattern: confirm the action, enable next step

**Part 1: Confirm (brief)**
- "All tasks completed." (for a task list the user cleared by finishing everything)
- "Inbox cleared."
- "Archive emptied."

**Part 2: Prompt next action (optional)**
Only if there is a clear natural next step.
- "Add your next set of tasks."
- "New messages will appear here as they arrive."

If there is no obvious next action, it is fine to leave the state with just the confirmation. Do not add a CTA for the sake of having a CTA.

---

## Illustration and Copy Integration

Illustrations are often part of empty states. When they are:

- Do not write copy that describes the illustration. Use the copy for what the illustration cannot show (the user's benefit, the next action).
- Align the emotional tone of the copy with the illustration. A whimsical illustration with a harsh error message is dissonant.
- If there is no illustration, the copy has to do more work. Add one line of context that an illustration would have provided visually.

## Examples: Complete Empty States

### Example 1: First-use (saved reports)
- Headline: "Your saved reports will appear here"
- Body: "Run a report and save it to find it quickly next time."
- CTA: "Run a report"

### Example 2: No-results (team member search)
- Headline: "No members match 'Caroline'"
- Body: "Check the spelling or search by email address."
- CTA: "Search by email"

### Example 3: Error (project loading failure)
- Headline: "We could not load this project"
- Body: "Refresh the page to try again. If the problem continues, your project data is safe."
- CTA: "Refresh page"
- Secondary: "Contact support"

### Example 4: Cleared (completed tasks)
- Headline: "All done for now."
- Body: "New tasks assigned to you will appear here."
